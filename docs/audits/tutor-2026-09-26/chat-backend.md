# Tutor chat/backend audit (read-only)

Scope: electron/ipc/tutorHandlers.ts, electron/ipc/aiHandlers.ts, src/lib/memory/ckrfMemoryService.ts, src/lib/db.ts, current tutor unit suites. Findings are static code evidence; no live provider session or behavioural benchmark was run in this subtask. Absolute project root: /Users/robmcarlson/Desktop/Neuron.

## Highest priority: learning data must represent evidence

1. **P1: Selecting a topic counts as successfully reviewing it.** tutorHandlers.ts:1046-1068 adds every requested topic and ID to topicsToLog, regardless of dialogue. :1094-1102 writes study log and clears has_new_material/is_gap; :1106-1123 defaults FSRS rating to Good when no strength/struggle matches. With API unavailable, malformed evaluation, abandoned session, or a quick review that only reached 1 of 20 requested topics, all targeted topics can become fresh. The early guard at :729 only requires two stored messages (even two assistant/system messages), not an attempted retrieval. Existing tests/unit/tutorSrsIntegration.test.ts:76 explicitly tests target IDs restoring retention to 100%, without requiring assessment evidence. Replace this success criterion. Separate target/introduced/practised/assessed; unassessed is unknown, never Good. Store topic-ID-linked answer evidence, assistance level, outcome, question/rubric/source IDs. Only eligible independent retrieval events advance retention; practice with explanation records learning without claiming recall.

2. **P1: Finalization is non-idempotent and not atomic.** tutorHandlers.ts:1365-1372 marks complete then always evaluates; :831 INSERT OR REPLACE evaluation doesn't prevent repeat mastery/SRS/misconception/episodic writes. Retry/double invoke increases repetitions and confidence for same answer; partial errors are swallowed at :1089-1129. Use explicit session finalization status, persisted assessment events with stable unique IDs, transaction for applying accepted events and completion metadata, retry-safe outbox or staged evaluation outside transaction. Test double/concurrent end, provider failure then retry, and injected DB failure.

3. **P1: Inferred prose is being treated as psychometric observation.** :752-765 asks for 1-4 strengths AND 1-4 struggles (encourages filling both even if evidence absent); :847-919 converts freeform concept strings into BKT correct/incorrect and Glicko difficulty=3 score=1/.25, then :1106 maps substring match to FSRS Easy/Again. No question rubric, confidence, independence, hint count or evidence quotation required. A strength after many hints can become Easy; recovered mistakes become a blanket failure. Schema must permit empty arrays and insufficient evidence, cite actual student turn IDs, distinguish initial recall from assisted learning, persist outcome per item. Treat model assessment as fallible, display/correct disputes, avoid escalating uncertainty into facts.

4. **P1: Topic identity can update wrong curriculum records.** :1003-1030 first substring / 50% word overlap chooses the first candidate, even generic 'analysis'; module preference only applies to earlier exact stages. :1064 and :1090 fall back to globally selected IDs without checking subject/module ownership, while SRS uses session.subject_id. Canonical topic IDs must be selected from allowed subject IDs; fuzzy matching should propose unresolved candidates, not mutate. Test similarly titled topics in multiple modules, foreign subject ID, renamed topic, punctuation, ambiguous freeform evidence.

5. **P2: Repeated success flips mastered back to good.** :854 CASE WHEN mastery_level='good' THEN 'mastered' ELSE 'good' means good -> mastered -> good. Canonical evidence state should replace this legacy toggle; short-term correction preserves mastered on validated success and tests three successive sessions.

6. **P2: Prefix truncation drops late evidence and source facts.** Evaluation :731-735 uses only first 8,000 characters; card generation :1545 uses first 10,000; chat :2060 keeps last 30 messages without rolling goal/evidence state or token accounting. Long sessions forget the initial learning contract while summaries miss later corrections. Incrementally assess/store evidence each turn, use compact rolling dialogue summaries with provenance and recent windows under model-specific token budget, summarize from persisted events rather than a transcript prefix. Test important error/correction after character 8,000 and early constraint after 30 turns.

## Source grounding and answer quality

7. **P1: Source awareness is confused with access to source content.** :1797-1814 samples fixed quartiles for long specific materials, :1886-1890 takes first three chunks for latest five documents selected at :1872-1875. Prompts :1827-1829 say never claim unavailable if outline contains concept. This encourages answering from general model knowledge when actual paragraph/formula hasn't been retrieved; older relevant docs are invisible. Reuse/index chunked materials and retrieve by active topic/question, include stable document/page/section citations, rerank and token budget, distinguish source quotation from tutor-generated application, offer unsupported/contradictory-source handling. Never conflate an outline with evidence. Test answer depends only on non-sampled chapter, sixth/oldest document, contradictory documents, document replacement, no source, prompt injection in uploaded text.

8. **P2: Prompt policy is sprawling and contradictory.** :1979-1984 mandates exact welcome + quiz; :181-200 beginner block instead demands explain then check. :117-122 mandates each response ends in another question and forbids ending early; this conflicts with user asking for an explanation, frustration, stopping, summary, or a short focused answer. :2010 / :2024 repeats always-question rules. Socratic phase :2023 refers to five-layer protocol defined only in a different phase prompt. Difficulty depth 5 :155 insists exhausting every angle until time ends. Replace with compact shared policy + explicit intent/mode + stateful pedagogy controller, honor stop and answer requests, one cognitive task/turn, demonstrate after bounded struggle, offer hint/worked example/check my reasoning. Time is a budget not obligation to interrogate. Prompt tests should assert mode precedence, but behavioural evals are essential.

9. **P2: Anti-repetition and adaptive difficulty are weak state heuristics.** :209-298 ignores uncertainty and freshness, uses exact topic or subject-wide average / raw count of strength vs struggle summaries; CKRF isn't driving this decision. buildMemoryBlock :309 drops mastery-only/weakness-only context; :335 forbids any repeated question (useful delayed retrieval should be allowed). CKRF memory :328 ignores _targetTopic and always fetches globally low ratings/top importance memories (:345, :372, :398), potentially burying target topic evidence. Use topic-specific baseline, bounded within-session adjustment, recency/confidence/evidence count, preserve voluntary difficulty choice; retrieve relevant memories and allow spaced variants. Keep misconception repair tied to diagnostic evidence, not three generic strengths (ckrfMemoryService.ts:254-291).

10. **P2: Card generation can immortalize student mistakes.** :1544-1546 calls entire dialogue source_material and :1570 demands derive solely from it; it does not retrieve primary course source or label incorrect student content as non-authoritative. Rigid 6-10 count, 3-5 repair quota and under-15-word answers can force low-quality cards. Generate proposed cards from verified source-backed takeaways/evidence, allow 0 cards, separate retrieval/application formats with appropriate rubric, attach provenance, keep user approval UI, semantic dedup across whole deck. :1585 increments cards_generated by 1 per generation call even before save (misleading counter).

## Runtime/session reliability

11. **P1: Streaming cancellation/hang protection incomplete.** tutorHandlers.ts:2073 creates controller but no exposed cancellation registry/handler; events :2082 use session ID only and send to first BrowserWindow (:1710), not requesting sender. aiHandlers.ts:451-452 removes caller abort bridge immediately after response headers; :477-499 reader.read has no idle/total deadline; :484 ignores [DONE] and keeps reading until closure; Gemini :386-393 is full response sliced into fake chunks and does not use caller signal. Add requestId to every chunk, sender-bound delivery, tracked abort with lifetime cleanup, idle/overall deadline, stop at DONE, provider adapter with true capability flags, stop/retry retaining only complete accepted turns. Test stale chunks after navigation/new request, cancellation after first token, stream stall after headers, premature EOF, malformed packet, rate limit, Gemini cancellation.

12. **P2: Response cleanup mutates valid technical content.** tutorHandlers.ts:1145-1160 globally collapses indentation, duplicate words and punctuation, including code/math/Vega strings despite comment saying not inside code/tables. Python nesting and intentional repeated-word language examples can be corrupted. Remove destructive cleanup or operate only on parsed prose nodes with tests preserving code byte-for-byte. Rendering should sanitize/validate diagrams separately.

13. **P1/P2: Message/session ownership model is a fragile FK bridge.** tutorHandlers.ts:55-82 creates conversations row matching tutor_sessions auto-ID; general chat without any subject cannot create row because conversations.subject_id NOT NULL (db.ts:313-331). saveMessage :1443 inserts regardless, so first-time general chat can fail with foreign_keys ON (main.ts:197). Separate explicit session conversation FK or unify conversation/session storage with nullable general scope; migrate preserving history and verify cascading deletes. Existing normal conversations ID collision is latent (no production non-tutor insertion located). Also :1449 writes ended_at for every saved turn, invalidating completion timestamp semantics; use last_message_at only and lifecycle state. :1487 selects oldest N messages for getMessageHistory; verify intended API then return most recent N chronologically if needed.

## Meaningful acceptance tests

- 20 targeted topics + 1 actual retrieval => precisely 1 eligible assessment; other 19 unchanged.
- 'I don't know', hint use, incorrect answer, unassessed intro, provider failure cannot silently register Good/Easy.
- Concurrent duplicate finalizations yield exactly one ledger application and one repetition per unique question evidence.
- No cross-user/subject/topic writes; exact canonical IDs survive renames.
- Long-session final misunderstanding and final corrected answer both represented in summary and their sequence preserved.
- Successful answer after hints differs from independent delayed retrieval; learner can dispute an outcome without deleting dialogue.
- Source-only fact in last chapter/older doc is cited correctly; unavailable evidence triggers uncertainty/retrieval instead of made-up certainty.
- Provider-stalled stream cancels promptly and has terminal state; retry produces one assistant turn; request/window isolation holds.
- First ever general chat works with zero subjects and DB FK checks pass after upgrade/cascade.
- Technical rendering preserves code indentation and chart string values.
- Behavioural eval set across STEM, humanities, novice/expert, partial semantic correctness, ambiguous question, repeated misconception, frustration, direct-answer request, and stop request. Grade evidence-grounded correctness, hint appropriateness, agency, one-task load, adaptation and coverage. Compare baseline and candidate blinded, with fixed cases and model versions; avoid claiming learning gains from prompt checks alone.
